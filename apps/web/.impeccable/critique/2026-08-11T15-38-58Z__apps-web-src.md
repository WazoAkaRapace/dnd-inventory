## Design Specificity Verdict

**Authored, but only to first base.** The parchment/blood/ink palette plus Cinzel display serif is a genuine, committed fantasy skin — this is not a generic Notion-clone. But the specificity is almost entirely *chromatic and typographic*. The *information architecture* and *interaction patterns* are unchanged from any CRUD inventory app: a search box, category/rarity selects, +/− steppers, a transfer modal. Nothing in the layout, copy voice, or data model evokes a character sheet, a backpack, or a dice roll. The visual language says D&D; the product behavior says "line-item manager with a tan theme."

**Deterministic scan:** 1 finding (gray-on-color at index.css:73) — confirmed FALSE POSITIVE. The detector's ±3-line context window fused `text-gray-700` (from `.rarity-common`) with `bg-green-100` (from `.rarity-uncommon`) — two separate CSS classes on two separate lines. Neither rendered element actually exhibits the antipattern.

**Console evidence (live API):** Assessment B discovered a P0 runtime bug — the frontend calls `GET /api/me` but the route is mounted at `/api/auth/me`, producing a 404 on every page load. The catch handler then clears the JWT and silently logs the user out on any full page reload. **FIXED** during this critique (auth.tsx:28).

## Overall Impression

A committed, attractive theme wrapped around an uncommitted, generic CRUD body. The encumbrance bar is genuinely excellent — rules-grounded, visceral, the one moment the app feels like D&D. Everything else is a functional but joyless line-item manager. The biggest opportunity is to stop being a two-column inventory spreadsheet and start being a character sheet.

## What's Working

1. **The encumbrance bar is genuinely well-designed.** Threshold markers as vertical lines, tier-colored fill, a tier label, and three numeric thresholds beneath — it communicates a multi-threshold rules system in ~80px. This component earns its place.
2. **Mobile-first correctness is real, not performative.** `text-base` on inputs, bottom-docked modals, sticky header on mobile only, `pb-24` clearance, `max-w-6xl` centering. Consistent responsive intent across every page.
3. **Domain copy is authentic French TTRPG vocabulary.** "Sac à dos," "Bourse," "Table du MD," "Surchargé." Someone who plays D&D in French wrote this. Label maps keep it DRY.

## Priority Issues

### [P0] Stepper-to-delete is a data-loss trap
**What:** Tapping − when quantity is 1 silently deletes the item — no confirmation, no undo, no toast.
**Why it matters:** The #1 trust failure for a tool used on a phone, one-handed, mid-combat. A single mis-tap destroys session-acquired gear.
**Fix:** At quantity 0, switch the row into a "confirm remove" state (grays out, − becomes trash confirm, auto-reverts after 4s) OR keep a 5-second undo toast after any delete.
**Suggested command:** $impeccable harden

### [P0] No success feedback on any mutation
**What:** addFromCatalog, saveCoins, toggleEquipped, transfers — none show success. If the network is slow, the user can't tell if the tap registered.
**Why it matters:** At the table with spotty Wi-Fi, "did it save?" is the most-asked question. Silent updates train users to re-tap, causing duplicates.
**Fix:** Lightweight toast system (250ms fade-in, 1.8s hold): "+1 Épée longue ajouté." Briefly highlight the affected inventory row.
**Suggested command:** $impeccable delight

### [P1] Two-column desktop split has no hierarchy; catalog buried on mobile
**What:** `lg:grid-cols-2` puts backpack and catalog side-by-side with identical weight. On mobile, the catalog falls *below* the entire inventory list — the most common action (add gear) is the least discoverable.
**Why it matters:** Adding an item requires scrolling past everything you own on the device it'll be used on most.
**Fix:** Catalog as a mobile FAB / bottom-sheet ("+ Ajouter" floating button → full-screen searchable sheet). Desktop: backpack primary at `lg:grid-cols-[3fr_2fr]`.
**Suggested command:** $impeccable layout

### [P1] Inventory row is a control salad; no grouping for long lists
**What:** One row holds: equipped checkbox, expand button, name + 2 badges, weight + total, −/qty/+ stepper, and a Transfer/Trash sub-row. At 375px this wraps awkwardly. No category grouping — a 25-item backpack is a flat scroll.
**Why it matters:** The row is where users live, and it asks them to parse 6+ pieces of info per item.
**Fix:** Group by collapsible category headers ("Armes · 3", "Équipement · 12"). Move Transfer/Trash into the expanded-details panel. Make equipped state a left-edge accent stripe, not a checkbox.
**Suggested command:** $impeccable distill

### [P2] First-run / help is zero
**What:** No onboarding, no tooltips, no explanation of encumbrance modes. A new DM hits "Variante (5/10/15 × FOR en kg)" with no idea what to pick.
**Why it matters:** The app assumes TTRPG literacy AND 5e-rules literacy AND variant encumbrance knowledge. First-session drop-off will be high.
**Fix:** Inline help on the mode selector (one-line plain-French per option, "Recommandé" tag). 3-step first-run overlay on the inventory page.
**Suggested command:** $impeccable onboard

### [P3] Coin purse is manual bookkeeping
**What:** Five raw number inputs + manual "Enregistrer." No quick-adjust, no auto-save, no conversion, no split-loot. Silver and platinum share the same emoji.
**Why it matters:** Treasure is the emotional payoff of D&D; here it's a tax form.
**Fix:** Auto-save on blur. +/− steppers per denomination. Distinct coin glyphs. GM "split loot" action.
**Suggested command:** $impeccable clarify

## Persona Red Flags

**Alex (Power User DM):** No keyboard shortcut to focus catalog search (no `/`, no Cmd+K). No "recently added" or "quick add" — re-searches Torches and Rations every session. No multi-add (5 Potions = 5 taps). Cannot distribute loot to multiple characters from GM dashboard. Will go back to paper.

**Sam (Accessibility):** The equipped checkbox label reads "équipé" with no item context — a screen reader announces "équipé, checkbox" 15 times with no way to know which item. No skip-to-content link. Modal has no focus trap. Trash button uses emoji with title but no aria-label. Encumbrance bar communicates state by color alone. Unusable at session speed.

**Casey (Distracted Mobile):** The −-to-zero-deletes behavior is Casey-specific — this is exactly the persona that triggers it. Two sticky headers (Nav z-30 + inventory header z-30, both top-0) will collide on mobile scroll. Coin purse "Enregistrer" button is easy to miss — unsaved gold lost silently on navigation away.

## Minor Observations

- Two z-30 sticky headers will collide on mobile (Nav in App.tsx and inventory header in CharacterInventoryPage.tsx both use sticky top-0 z-30).
- `max-w-6xl` main with `pb-24` padding implies a bottom nav that doesn't exist — dead space on mobile.
- `color-scheme: light dark` is set but the app is entirely light-themed — native form controls render dark on macOS dark mode and clash.
- `Inter` font is loaded (~30kb) but never used — font-body is Iowan/Palatino, font-sans is never referenced.
- No favicon / PWA manifest — matters for "add to home screen" at the table.
- No 404 page — `path="*"` silently redirects to /parties.
- Empty encumbrance bar shows "0.00 / X kg" — toFixed(2) on a whole-number backpack looks oddly precise.

## Questions to Consider

1. What if the inventory page were a character sheet, not a spreadsheet? A paper-doll + backpack layout would transform specificity from "themed" to "authored."
2. What is the single most common action, and how many taps does it take? "Adjust quantity of a consumable during combat" is 3-4 taps with scrolling. Could there be a "combat mode" that pins consumables?
3. Should this app ever show a die? The entire emotional payoff of D&D — rolls, crits, loot reveals — is absent. Even a tiny touch would shift the product from "inventory database with a tan theme" to "a thing that feels like playing."
